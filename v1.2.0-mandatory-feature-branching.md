## 1. Executive Summary

In agentic software development, AI agents frequently perform edits and execute commits across projects. To prevent accidental commits directly onto production base branches (`main`, `master`, `release`), this specification establishes a mandatory feature branch policy across all supported agent frameworks: **Google Antigravity**, **Claude Code**, **GitHub Copilot**, **Cursor**, and **Windsurf**, as well as the global Antigravity **gated-coding-pipeline** plugin.

---

## 2. Core Policy Mandates

### 2.1 Branch Verification & Creation (Phase 3)
Whenever an agent begins implementation on any Git repository:
1. Inspect the active branch using `git branch --show-current`.
2. If currently on a base or protected branch (`main`, `master`, `release`, etc.), the agent **MUST** automatically create and check out a dedicated feature branch prior to or during changes:
   ```bash
   git checkout -b feat/<descriptive-feature-name>
   ```
3. If already on an active feature branch, continue working on that branch without creating redundant sub-branches.
4. If the workspace is not a Git repository, proceed with standard file modification and suggest repository initialization if appropriate.

### 2.2 Feature Branch Commit Enforcement (Phase 5)
1. Before staging intentional files, verify that the current branch is indeed a feature branch.
2. Committing directly to `main` or `master` is **strictly prohibited**.
3. All commits must be made to the designated feature branch with a Conventional Commit message referencing the target version:
   ```bash
   git commit -m "feat(v1.2.0): implement mandatory feature branch policy across agents"
   ```

### 2.3 Strict Deviation Boundary
Agents are **strictly forbidden** from deviating from this policy on their own judgment. An agent may **ONLY** commit directly to `main`/`master` if the user explicitly and specifically instructs:
> *"Commit directly on main"* or *"No new branch, commit on master"*

In the absence of an explicit user directive, the mandatory feature branch rule applies unconditionally.

### 2.4 Remote Push Guard
The standing rule remains absolute: **NEVER execute `git push`** unless specifically requested by the user.
